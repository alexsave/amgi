# amgi: add Anki cards from the command line

amgi writes decks and notes into the user's real Anki collection, with card text and audio generated by Gemini.
Desktop Anki must have been opened once, so that it has made a profile; after that it must be CLOSED while amgi writes.
amgi checks for an open Anki itself (a `-wal` or `-shm` beside the collection counts as open) and exits 2, so do not check for Anki or look for `-wal` files before a command.
Before its first write amgi copies the collection to `amgi-collection-backups/` beside `collection.anki2`.
Never edit `collection.anki2` yourself.

## Install once (from the repository root)

An installer or the user does this once per checkout; an agent whose folder already has `server/build/amgi` skips straight to "Each time".
Prerequisites: make, Xcode's command line tools, and `brew install sqlite icu4c@78 openssl@3`.
`make server` prints only a few lines (no compiler output); clone, submodules and build take about 8 seconds end to end (clone 1 s, submodules 3 s, build 4 s).

```bash
git submodule update --init --recursive
make server
```

## Each time

```bash
server/build/amgi up --key-file /path/to/.env.local
server/build/amgi deck add "Spanish" --from en --to es
server/build/amgi card add --deck "Spanish" --text "Where is the station?" --from en --to es
server/build/amgi card add --deck "Spanish" --file phrases.txt
server/build/amgi card list --deck "Spanish"
server/build/amgi audio fill --deck "Spanish"
server/build/amgi down
```

A deck carries its languages: the language the user knows (`--from en`, the card's front, the cue) and the one being learned (`--to es`, the back).
The deck's pair alone decides every card made in it, so `card add` needs no `--from` and `--to` once the deck has them: `card add --deck "Spanish" --text "Where is the station?"` is enough.
Set a deck's languages with `deck add NAME --from K --to L`.
A deck that has none (every deck from before this) is asked first: amgi reads its own cards, and with a key asks Gemini once, and stores the pair only when certain, and says so on stderr.
When that finds nothing, `card add` exits 4 `the deck has no languages yet: pass --from and --to` (with a guess, if there is one); pass `--from` and `--to` once, and they are stored on the deck.
`card add` with `--from` or `--to` that are not the deck's own exits 4, names the deck's pair, and adds nothing: never work around it, ask the user which pair the deck is.
The input to `--text` can be in any language: it is only the meaning, and the card is made in the deck's pair.
Language codes: `en`, `ko`, `ja`, `zh_cn`, `zh_hk`, `es`, `fr`, `pt`, `ru`, `id`, `de`, `tr`, `vi`, `it`, `th`, `hi`, `ur`, `ar`.
`deck add NAME --from KNOWN --to LEARNING` also stores the deck's language pair in the deck (both flags or neither; the same codes), so Anki and the page see it too; `deck list` prints it.
`card add --deck D --front TEXT --back TEXT` makes a card with no Gemini call and no audio (front in the deck's known language, back in its learning language).
A write prints what reading it back finds.
Output is tab-separated: `deck ID NOTES NAME KNOWN LEARNING` (`-` and `-` when the deck has no pair), `would-remove ID NOTES CARDS SUBDECKS NAME` and `removed ID NOTES CARDS DECKS NAME` (for `deck remove`), `would-remove ID FRONT BACK` and `removed ID FRONT BACK` (for `card remove`), `note ID FRONT BACK CUE_AUDIO TARGET_AUDIO` (`-` when absent), `skip REASON PHRASE`, `fail REASON PHRASE`, `left REASON PHRASE` and `bulk ADDED SKIPPED FAILED NOT_DONE` (for `card add --file`), `filled ID`, `failed ID REASON` and `audio-fill FILLED UP_TO_DATE SKIPPED FAILED` (for `audio fill`), `status MODE SCHEMA PID PORT PROFILE COLLECTION`, `install READY ADDONS UP_TO_DATE NOTE_TYPE_CHECKED`.
Exit codes: 0 ok, 1 other (amgi not up, server error), 2 locked, 3 not found, 4 usage (also: a deck with no languages and none given, or others than its own), 5 Gemini.
`deck add` is find-or-create: the same name again prints the same deck line, exits 0, and says `amgi: the deck was already there` on stderr.
With `--from` and `--to` the pair is set on the deck it found or made, replacing one it had.
A code that is not one of the languages, or the same code twice, is refused before anything is made: exit 4, the sentence naming the codes, and no deck.
`--from` without `--to` (or the reverse) is exit 4 too.
`up` serves on 127.0.0.1:3000 in the background (`--port N`; `--profile NAME` when there are several); pid file `server/build/amgi.pid`, log `server/build/amgi.log` (both in the directory `AMGI_STATE_DIR` names, when that is set).
A second `up` from the same checkout prints `amgi up: already running pid=... port=...` and exits 0.
Another checkout's `up`, or `make start`, on the same port makes `up` exit 1 with "Address already in use": pass `--port`.
`deck remove NAME` deletes nothing: it prints what a delete would take (`would-remove`) and says to pass `--yes`.
`deck remove NAME --yes` deletes the deck, its subdecks, their cards and the notes left with no card, and prints `removed`.
It matches the exact name only (none: exit 3), refuses the Default deck (exit 4), and deletes nothing in either case.
The audio files of a removed deck stay in `collection.media` until Anki's Tools > Check Media.
`card remove ID` deletes nothing: it prints `would-remove ID FRONT BACK` and says to pass `--yes`.
`card remove ID --yes` deletes that one note, its cards and their review history, and prints `removed ID FRONT BACK`.
`ID` is the note ID that `card list` prints after `note`; an ID that is no note exits 3, and a missing or non-numeric ID exits 4, both deleting nothing.

## Many phrases from a file

`card add --deck NAME --file PATH` makes one card of every phrase line of the file, in the deck's pair, through the same generation as `--text`; `--file -` reads standard input.
Give `--from` and `--to` here exactly as for `--text` (only for a deck that has no pair).
The file is read as the deck page reads a paste: one phrase a line, each line trimmed, blank lines and `[section]` marker lines passed over.
A line in any language is only the meaning, and the card is made in the deck's pair.
A file over 65536 bytes is refused whole with exit 4, and nothing is added (a missing file is exit 4 too).
A run makes at most 500 phrases: the first 500 are made, the rest print `left limit` and the exit is 4; run those again, or split the file.
Each card is written as soon as it is made, so a run that stops leaves the cards it made in the deck.
Each phrase prints one line, in the file's order:

- `note ID FRONT BACK CUE_AUDIO TARGET_AUDIO` is a card made and written;
- `skip repeat PHRASE` is a line that repeats an earlier line of the file (compared by its text without surrounding white space and trailing punctuation);
- `skip in-deck PHRASE` is a line the deck already holds as a note's Cue or Target, so running the same file again adds nothing and asks Gemini nothing;
- `fail REASON PHRASE` is a phrase that could not be made or written, and the run goes on;
- `left REASON PHRASE` is a phrase the run did not reach: REASON is `dailyCap`, `no-key`, `locked` or `not-up` (what stopped the run), or `limit` (past the 500 phrases).

The last line is `bulk ADDED SKIPPED FAILED NOT_DONE`, the run's counts.
The exit is 0 when every phrase was made or skipped, 5 when the day's cap or a missing key stopped the run or Gemini failed a phrase, 2 when Anki had the collection, and 4 when lines are left with `limit`.
Gemini's per-minute limit is waited out and the phrase asked again (a line on stderr says so).
`dailyCap`: stop and tell the user; the cards made stay.
A file makes a Gemini call (and two clips) for every line it adds: say how many lines it holds before a long run.

## Filling in audio that is missing

`audio fill --deck NAME` makes the clip of every note in the deck (subdecks included) that lacks one, in the deck's languages, one note at a time, and writes its reference into the note's audio field.
With no other option it fills the amgi Listening notes, both sides (Target into TargetAudio, Cue into CueAudio).
For another note type name its fields: `audio fill --deck NAME --notetype Basic --text-field Front --audio-field Back [--side learning|known] [--form sound|html]` (`--side` is which of the deck's two languages the text field is in, `learning` unless said; `--form sound` writes `[sound:x]`, `html` an `<audio>` element).
It leaves alone a note that already has the clip of its current text and a note whose audio field holds someone else's audio (counted as up to date); it never touches an image; running it again fills nothing.
It prints `filled ID` or `failed ID REASON` for each note it tried, and last `audio-fill FILLED UP_TO_DATE SKIPPED FAILED` (the notes it found up to date, which includes those with someone else's audio, and the ones with no text or of another note type, are counted, not listed).
It waits as Gemini's rate limit asks and stops at once on the day's quota (exit 5), with the notes done staying done; a note whose clip Gemini could not make is `failed` and the run goes on, ending with exit 5.
A deck with no languages is exit 4, like `card add`.
Each clip is a Gemini call: do it when the user asks, and say how many notes the run will take (`audio fill` runs the plan first, but it does not stop to ask).

## Which commands write

Read-only: `status`, `deck list`, `card list`, and `deck remove` and `card remove` without `--yes`.
Writes: `deck add`, `card add`, `audio fill`, `deck remove --yes`, `card remove --yes`, `install`.
`card add --text` and `card add --file` store two audio clips in `collection.media` as soon as Gemini answers, even if no note is then added.
Ask the user before `deck remove --yes` on a deck, or `card remove --yes` on a note, that the user did not ask to delete.
`install` is NOT part of adding a card: when amgi is installed, `amgi status` prints a line starting `install<TAB>yes`; run `amgi install` only when the user asks.

## The key and Gemini's limits

Give the key only as a file path (`--key-file`, or `CBASE_ENV_FILE`), a `KEY=VALUE` file with `GEMINI_API_KEY`.
Never read, print or copy the value.
Without a key `--text` and `--file` exit 5 and `--front/--back` still works.
A card costs 2 voice requests (one more for each retake) and 3 to 5 text requests.
Each model has its own daily limit, set by the key's tier; when it is reached amgi stops with `dailyCap` and names the limit Google gave.
The free tier is too small for a real deck, so say before a long run that it needs billing on the key's project.

## Not working?

Exit 2 `locked: ask the user to close Anki`: ask, then run the command again.
Exit 5 `rate limited`: the CLI already waited as asked; wait `retryAfterMs` and retry.
`dailyCap`: stop and tell the user.
After the writes, the user opens Anki and syncs; if AnkiWeb asks to upload or download the whole collection, upload.

Raw HTTP API, wire format, the bridge, scripting and the card-design rules: skills/amgi/references/api.md and the other references.
