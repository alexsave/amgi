# amgi: add Anki cards from the command line
amgi writes decks and notes into the user's real Anki collection, with card text and audio generated by Gemini.
Desktop Anki must have been opened once, so that it has made a profile; after that it must be CLOSED while amgi writes.
amgi checks for an open Anki itself (a `-wal` or `-shm` beside the collection counts as open) and exits 2, so do not check for Anki or look for `-wal` files before a command.
Before its first write amgi copies the collection to `amgi-collection-backups/` beside `collection.anki2`; never edit `collection.anki2` yourself.

## Quick start (from the repository root; no Node needed)
Prerequisites: make, Xcode's command line tools, and `brew install sqlite icu4c@78 openssl@3` (then `make server` prints only a few lines, no compiler output, and takes about 5 seconds on a clean checkout).

```bash
git submodule update --init --recursive
make server
server/build/amgi up --key-file /path/to/.env.local
server/build/amgi deck add "Spanish"
server/build/amgi card add --deck "Spanish" --text "Where is the station?" --from en --to es
server/build/amgi card list --deck "Spanish"
server/build/amgi down
```

`--from en` is the language the user knows (the card's front, the cue); `--to es` is the language being learned (the back); codes: `en`, `ko`, `ja`, `zh_cn`, `zh_hk`, `es`, `fr`, `pt`, `ru`, `id`, `de`, `tr`, `vi`, `it`, `th`, `hi`, `ur`, `ar`.
`card add --deck D --front TEXT --back TEXT` makes a card with no Gemini call and no audio.
Output is tab-separated, and a write prints what reading it back finds: `deck ID NOTES NAME`, `note ID FRONT BACK CUE_AUDIO TARGET_AUDIO` (`-` when absent), `status MODE SCHEMA PID PORT PROFILE COLLECTION`, `install READY ADDONS UP_TO_DATE NOTE_TYPE_CHECKED`.
Exit codes: 0 ok, 1 other (amgi not up, server error), 2 locked, 3 not found, 4 usage, 5 Gemini.
`deck add` is find-or-create: the same name again prints the same deck line, exits 0, and says `amgi: the deck was already there` on stderr.
`up` serves on 127.0.0.1:3000 in the background (`--port N`; `--profile NAME` when there are several); pid file `server/build/amgi.pid`, log `server/build/amgi.log`.
A second `up` from the same checkout prints `amgi up: already running pid=... port=...` and exits 0, while another checkout's `up` (or `make start`) on the same port makes `up` exit 1 with "Address already in use", so pass `--port`.

## Which commands write
Read-only: `status`, `deck list`, `card list`; writes: `deck add`, `card add`, `install`.
`card add --text` stores two audio clips in `collection.media` as soon as Gemini answers, even if no note is then added.
`install` is NOT part of adding a card: when amgi is installed, `amgi status` prints a line starting `install<TAB>yes`; run `amgi install` only when the user asks.

## The key and Gemini's limits
Give the key only as a file path (`--key-file`, or `CBASE_ENV_FILE`), a `KEY=VALUE` file with `GEMINI_API_KEY`; never read, print or copy the value.
Without a key `--text` exits 5 and `--front/--back` still works.
A card costs 5 to 7 Gemini requests and the free tier allows 10 a day per model, so a real deck needs billing on the key's project: say so before a long run.

## Not working?
Exit 2 `locked: ask the user to close Anki`: ask, then run the command again.
Exit 5 `rate limited`: the CLI already waited as asked; wait `retryAfterMs` and retry. `dailyCap`: stop and tell the user.
After the writes, the user opens Anki and syncs; if AnkiWeb asks to upload or download the whole collection, upload.
